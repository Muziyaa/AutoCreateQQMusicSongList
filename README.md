# QQ 音乐歌单批量导入工具

一个运行在 QQ 音乐网页版上的 Tampermonkey 油猴脚本，用来把 `song,artist` 格式的 CSV 歌曲列表，批量添加到你指定的 QQ 音乐歌单中。

如果目标歌单不存在，脚本会先尝试自动创建，再继续导入。

当前主脚本文件是 [qqmusic_playlist_import.user.js](/Users/muziyaa/Project/AutoCreateQQMusicSongList/qqmusic_playlist_import.user.js)。

## 项目简介

这个工具的核心目标是：

- 复用你当前浏览器里已经登录的 QQ 音乐账号
- 尽量减少手工点击
- 用本地 CSV 批量导入歌曲
- 尽可能保守地匹配搜索结果，避免误加错歌

它不是直接调用公开 API，而是基于 QQ 音乐网页实际页面做自动化操作，包括：

- 自动跳转到“我创建的歌单”
- 自动检查歌单是否存在
- 自动创建歌单
- 自动搜索歌曲
- 自动识别候选结果
- 自动打开“添加到歌单”菜单
- 自动选择目标歌单

## 适用场景

适合：

- 你已经整理好一份歌单列表，想一次性导入 QQ 音乐
- 你的歌曲数据可以整理成 `歌名 + 歌手`
- 你希望在网页端完成导入，而不是写 Python、Selenium 或抓接口
- 你希望尽量保留“人工可控”的保守匹配逻辑

不太适合：

- 只有歌名，没有歌手
- 需要 100% 全自动处理所有同名、多版本、翻唱、Live、DJ、纯音乐、改编曲
- 手机端网页或 QQ 音乐 App 场景

## 开发与分析流程

这个工具最初不是靠公开接口文档完成的，而是通过对 QQ 音乐网页端的实际页面结构进行本地分析后逐步编写出来的。

整体流程大致如下：

### 1. 打开 QQ 音乐网页版目标页面

先在浏览器中打开与任务相关的页面，例如：

- 我的音乐页
- 我创建的歌单页
- 搜索结果页
- 单曲列表页
- 添加到歌单弹出菜单出现时的页面

这些页面是后续分析按钮、歌单列表、歌曲行、弹层结构的基础。

### 2. 本地保存网页快照用于分析

为了在离线状态下反复分析页面结构，可以把网页另存为本地 HTML 快照，并保留浏览器生成的配套静态资源目录。

这样做的好处是：

- 可以反复检视 DOM 结构
- 可以用本地搜索工具快速查找 class 名、按钮文本和组件结构
- 可以比直接在线反复点页面更稳定
- 有利于分析 QQ 音乐前端打包后的页面和样式

### 3. 从快照中提取关键页面锚点

在本地分析时，重点会找这些内容：

- “新建歌单”按钮的位置和 class
- “我创建的歌单”页的歌单列表结构
- 搜索结果列表里每一行歌曲的结构
- 歌名节点、歌手节点、操作按钮节点
- “添加到歌单”菜单对应的弹层结构
- 添加成功或已在歌单中的提示文本

这些锚点会直接决定脚本里的选择器和等待逻辑。

### 4. 编写脚本的 DOM 自动化逻辑

在拿到页面锚点之后，再把流程写进油猴脚本：

1. 检查是否登录
2. 跳转到“我创建的歌单”
3. 查找或创建目标歌单
4. 逐首搜索歌曲
5. 提取候选歌曲标题、歌手和按钮
6. 对候选做保守匹配
7. 打开“添加到歌单”菜单
8. 选择目标歌单
9. 检查页面是否真的提示添加成功

### 5. 用真实导入日志反向修正脚本

脚本不是一次写完就稳定的，而是结合真实导入日志不断修正的。

例如这类问题都来自实际运行后的日志反馈：

- 候选全部歧义
- 标题里混入 `MV`、`播放`、`分享` 等脏文本
- 原版和合唱版同时出现
- 菜单打开了但并没有真的加入歌单
- 日志显示成功，但歌单里没有歌曲

针对这些问题，脚本后来逐步增加了：

- 标题清洗
- 版本变体识别
- 歌手集合匹配
- 更严格的成功提示判定
- 更详细的歧义日志

### 6. 小批量验证后再跑完整歌单

实际推荐的开发/调试方式是：

1. 先用少量歌曲测试
2. 看日志是否能正确识别候选
3. 检查歌单里是否真的成功添加
4. 修正后再跑完整 CSV

这样可以显著减少一次性跑完整歌单带来的误判成本。

### 7. 页面快照文件仅用于本地分析，不建议上传

需要特别说明的是：

- 本地保存的网页 HTML 快照和配套资源目录，只用于本地分析
- 它们不属于工具运行必需文件
- 不建议上传到 GitHub
- 也不建议放进最终公开发布内容

仓库已经通过 `.gitignore` 将这类本地页面快照排除，避免误上传。

## CSV 文件格式

脚本固定要求 CSV 表头为：

```csv
song,artist
```

示例：

```csv
song,artist
六月的雨,胡歌
半城烟沙,许嵩
犯贱,徐良/阿悄
七里香,周杰伦
```

规则说明：

- 第一行必须包含 `song,artist`
- `song` 表示歌名
- `artist` 表示歌手
- 多歌手可以写成 `徐良/阿悄`
- 推荐使用 UTF-8 编码
- 空行会被忽略
- CSV 内重复的 `song + artist` 会自动去重
- 如果歌名里包含逗号，需要符合标准 CSV 引号规则

## 匹配策略说明

这个工具不是“搜到第一个结果就加”，而是做了比较保守的候选判断。

### 标题清洗

脚本会先清掉页面里混入的噪音，例如：

- `MV`
- `VIP`
- `SQ`
- `HQ`
- `播放`
- `分享`
- `添加到歌单`

### 变体识别

脚本会尽量识别并降低这些变体的优先级：

- `live`
- `dj版`
- `remix`
- `mix`
- `demo`
- `伴奏`
- `纯音乐`
- `钢琴版`
- `合唱版`
- `广场舞版`

### 歌手匹配

脚本会把歌手拆分成集合比较，例如：

- `徐良/阿悄`
- `许嵩/何曼婷`

并优先以下顺序：

1. 歌手集合完全匹配
2. 原始歌手文本完全匹配
3. 目标歌手被完整覆盖但存在额外歌手
4. 仅做松散匹配

这能减少误选这类情况：

- 原版 vs 合唱版
- 原版 vs 二创拼盘版
- 原版 vs 带营销前缀的账号名

### 为什么仍然会歧义

有些歌曲在 QQ 音乐搜索结果里确实存在多个非常接近的版本，例如：

- 原唱版
- 原唱参与的合唱版
- 原唱参与的翻唱合集版
- 不同发布时间的同名曲

当脚本无法安全判断时，会标记为 `ambiguous` 并跳过，而不会盲目添加。

## 日志状态说明

日志中的状态含义如下：

- `added`
  检测到添加成功提示，认为已加入歌单

- `skipped`
  歌曲可能已在歌单中

- `not_found`
  没找到可用候选

- `ambiguous`
  候选过多，无法安全判断，已跳过

- `failed`
  过程执行失败，例如没找到按钮、没检测到成功提示、菜单点击异常

## 常见问题

### 1. 歌单不存在怎么办

脚本会先到“我创建的歌单”页查找。

如果找不到，会尝试点击 `新建歌单` 自动创建，然后继续导入。

### 2. 为什么有些歌会显示歧义

通常是这些原因：

- 搜索结果里有多个同名版本
- 目标歌手参与了多个版本
- 存在 Live、DJ、Remix、Demo、纯音乐、广场舞等变体
- 搜索结果里混入二创或营销账号

### 3. 为什么日志显示成功，但歌单里不一定有

旧版本曾经存在“只要没报错就认为添加成功”的问题。

当前版本已经收紧逻辑，要求：

- 先找到真正的添加菜单
- 再点击目标歌单
- 然后观察页面是否出现成功提示

如果没有检测到成功提示，会记为失败，而不是假阳性成功。

### 4. 为什么有些歌搜不到

可能原因：

- 歌名或歌手写法与 QQ 音乐库不一致
- 歌曲已下架
- 该歌曲在 QQ 音乐中使用了不同版本标题
- 搜索结果结构发生变化

### 5. 为什么建议一定写歌手

只写歌名时，同名歌太多，误匹配概率会显著上升。

## 本地数据保存说明

脚本为了支持任务继续执行，会把任务状态保存到浏览器本地 `localStorage`。

当前会使用这些 key：

- `__qqmusic_playlist_import_job_v1__`
- `__qqmusic_playlist_import_last_playlist__`

其中可能包含：

- 目标歌单名
- 当前导入歌曲列表
- 导入日志
- 上一次使用的歌单名

这些数据只保存在你本机浏览器的 `y.qq.com` 域名下，不会主动上传到第三方。

## 隐私与安全说明

当前脚本已经做过检查，结论如下：

- 没有 `fetch`
- 没有 `XMLHttpRequest`
- 没有 `WebSocket`
- 没有 `sendBeacon`
- 没有向第三方服务器发送导入内容
- `document.cookie` 只用于判断是否登录，没有上传或打印
- CSV 文件通过浏览器本地读取，不会主动外发

这意味着：

- 发布脚本源码到 GitHub，通常没有问题
- 发布到油猴平台，脚本本身通常没有问题

但仍然建议不要公开这些内容：

- 你的实际运行日志
- 你的歌单截图
- 带登录态的浏览器抓包
- 本地导出的 `localStorage`

## 推荐使用建议

为了减少误差，建议按下面方式使用：

1. 先用 3 到 5 首歌做小批量测试
2. 确认歌单创建、搜索、添加都没问题后，再跑完整 CSV
3. 导入前先点一次“清除任务”
4. 导入结束后如果在意本地残留，再点一次“清除任务”
5. 对少量 `ambiguous` 歌曲单独手工处理，效率更高
